## 2. 杆回中与目标归零不是同一时刻

真实路径为 `ano_xy_stick`（有效IMU时间驱动的1ms任务）→20ms XY回调捕获完整杆量/速度/加速度/航向元组→速度P/I/前馈→角目标→flight_core选择→姿态/角速度环。

- [ano_xy_stick.v](../../../firmware/B0B3/source/position/ano_xy_stick.v):53–66：CH2前向、CH1右向；原始偏差±50us以内为零；死区外减50，再乘.0022；3Hz LPF按每个完成的1ms步迭代，保留定点余数，再做二维长度限幅。
- [mtf_xyz_navigation_control.v](../../../firmware/B0B3/source/mtf_xyz_navigation_control.v):217–241、280–288：独立20ms计时器，传入 `position_dt_us=20000`；导航包的 `dt_us` 是几何/源记录间隔，**不能当作这条速度控制回调dt**。
- [mtf_xyz_hold_control.v](../../../firmware/B0B3/source/position/mtf_xyz_hold_control.v):311–345：先捕获回调及其完成的杆滤波状态，数学等待不会把较新输入替入旧元组。

新增真实 RTL `stick_tail` 试验使用冻结的 `ano_xy_stick`/真实除法器：满杆稳定后回中，滤波归至原幅1%需247ms、0.1%需371ms；500ms剩6个Q16最低位。1450/1550为死区，1551仍保留144Q16微小目标，没有整数舍入死区。Python按 P2 的 LPF 方程计算，同输入最大差0.88945个Q16最低位。**这里执行的是RTL和Python方程模型，没有编译或执行P2 C。**

因此不能把首个中心杆主帧当作滤波速度目标恰为零；但上述持续1.3s、角目标多次反向且达约±10°的现象，不是一次回中输入的单调滤波尾巴所能单独解释。这个判断仍以未观测到的200ms帧间动作和传感器/动力未知为边界。

## 3. 有P刹车，无显式位置锁定；P2纯OF亦如此

以航向对齐的身体轴、mm/s与cdeg表示，真实算式是：

```
v_cmd = completed_3Hz_stick * clip(1.5 * height_mm, 500, 1500)
e_I   = v_cmd - heading_aligned_fused_velocity
e_P   = e_I - 0.03 * acceleration_LPF_5Hz
P     = round(e_P * P_wire / 1000)
I    += round(round(clip(e_I, ±500) * dt_us / 1e6) * I_wire / 1000)
I     = taking_off && I_wire != 0 ? clip(I, ±1000cdeg) : 0
FF    = round(v_cmd / 5)
roll  = clip(trunc(P_y + I_y + FF_y), ±2500cdeg)
pitch = clip(trunc(-(P_x + I_x + FF_x)), ±2500cdeg)
```

I中不含.03s加速度提前；这个提前属于P反馈，不能与设定值前馈FF混为一项。默认P=.05对应内部乘数.5cdeg/(mm/s)，所以中心杆、加速度项接近零、观察到右向500mm/s时，P本身会命令约−2.5°横滚刹车，而不是回中后完全自稳零角。

新增真实控制器+真实 `nav_math_service` 试验实际得到−249cdeg（整数截断边界），I=0；随后反馈速度归零，目标也归零。另一个实例连续改变输入x/y，并将 `POSITION_KP_Q16` 从65536改32768，49次回调的roll/pitch/active与原实例逐周期一致。源码读写锥也显示：`target_x/y`、`position_ex/ey_store`虽赋值，未进入后续角目标运算；遗留的 POSITION_KP 只影响未用存储宽度。这是明确的速度环架构，定向RTL证据不是全状态形式证明。

`controller_position_trace.csv` 的 `phase/ch1/vy_q16/x/y` 是发布时测试驱动的**当前输入**，`captured_norm/desired/P/I/FF` 是已完成回调的状态/实际数学结果，两者不可混成同一采样边沿。例如902ms条目已把live速度改为零，但仍发布刚才捕获500mm/s的旧回调，因此P仍是刹车值；下一次新回调才反映零速。这里没有把该正常元组流水现象误判成错用反馈。

I=0去掉的是这个外环的累计速度误差/稳态偏置补偿，**不是所有积分器**：速度融合、Z环、姿态率环的积分未因此关闭。无显式位置环时，速度归零后不会根据“离回中点多远”再生成拉回目标。非零I的累计速度误差可以产生类似相对位移的恢复作用并保持静态倾角补偿，但其参考、限幅、航向、模式保留/重置均不同于一个明确的位置锁定环，不能说打开I就等于定点锁位置。

P2 `Ano_LocCtrl.c:198–256` 的纯OF分支同样是 `fs.speed_set_h` 对速度反馈的P+I+FF；没有位置误差外环。真正 `hope_latitude/longitude_err → ne_pos_control → speed target` 位于GPS分支约332–353行，UWB另有模式分支。不能把P2的GPS位置逻辑或本工程另一个未实例化控制器，套到本机纯光流模式。

## 4. 边界和状态：确认机制，尚无具体实现错误反例

必须区分两种滤波状态：3Hz杆滤波在RC有效且未origin_reset时继续更新，CH7低档也在跑；5Hz加速度滤波与XY I在有效XY回调中更新。普通XY关闭会取消/回滚半事务，保留最后一次完整的I与5Hz滤波；全局取消、origin/height/enable撤销则清这些状态。P2的 `Loc_1level_PID_Init` 只重设参数，没有清PID积分或该静态LPF，普通ATT分支也不调用OF PID；并不是“切模式就应全部清零”。

XY观测资格丢失时，速度融合可清零/重新建立连续性，而控制器可能只发生XY取消，保留完成的I/加速度LPF；这构成一个具体的恢复瞬态通路。**它可影响后续响应，但不能倒置时间顺序：**V15 seq285–292的大摆动先于293的pitch+16.15°/XYready撤销；487–494的横滚往复也先于500的roll+15.13°撤销。因而这两次可见摆动不能把15°门限与随后的融合清零当作首次触发源。293/500失效时的零融合速度也不能当作飞机真的停止。

在已查范围内，没有找到死区边界、.0022/单位倍率、1ms/20ms dt、前馈加和、模式半事务回滚的具体实现错误反例；没有为获得平稳曲线而改源或改状态策略。B3新增的增益接口/位宽/快照重构不能解释发生于旧V15的原始振荡。确认的“预期差异”是速度保持与显式位置锁定不同；确认的“动态症状”是V15中杆后的外环目标本身仍在摆动。旋转污染、真实平移、内环/动力相位、外环I/偏置与高度耦合目前不能凭这两份5Hz日志唯一分离。

## 5. 为什么不从日志伪造P/I/FF重建，以及最小下一步

旧A582没有完成的1ms滤波杆量、20ms实际捕获的输入、5Hz内部加速度LPF、实时I、各P/FF项和取消事件；主帧航向/导航速度也不必等于同一20ms回调的采样元组。[response_rows.csv](response_rows.csv)把这些字段明确留空，仅另列“当前快照速度旋回航向轴”和“零目标P-only参考”；后者不是实测P项。没有把5Hz RC阶梯保持后代入模型冒充真实历史。

最小可辨识验收是先做离线/停机诊断的**有界回调录波**：同一回调记录raw RC、完成的杆滤波/目标速度、捕获速度与航向、dt、加速度LPF、P/I/FF、限幅前后角、publication id、taking_off、XY/Z资格/取消与高度首次撤销事件；在回中或资格丢失时冻结前后窗口，停机后读出。这样无需把大流量诊断塞进现有无线5Hz流。先确认这些链路与独立速度/位置参考一致，再设计同步外部位置真值的单轴动作/回中试验；所有后续硬件/带桨动作另行取得授权。本报告不无条件推荐增益，也不把I=0、P偏小或旋转关联直接宣布为唯一根因。
