## 分母、返回归属和保留值

所有实际请求分母为正literal：5/20/100/1000/10000/65536/1000000/106908，或`10000000+314dt`。dt只从直接合法1000..100000的position_update接纳，动态分母在**[10314000,41400000]**，计算不发生uint32溢出。实际请求最小分母5；den寄存器初始1只属于闲置值，不是一个未经calc配对的请求。所有有效num远离INT64_MIN，因此真实divider不会因合法调用出现除0或abs(INT64_MIN)错误。

`num`仅initial0和state100 `if(md)`写入匹配product；同沿den从本次pending_den更新，div_start才置1。服务下一拍才看见请求，因而采到的是配对的新num/den。`value_store`仅initial0和state101 `if(dd && !derr)`写quotient；derr路径只置blocked、退0，没有捕获错误商。reset/cancel本来不清这些寄存器，但保留的是已证明有界的旧值，不需要也不应新增reset。

真实nav_math_service以done的response_owner、epoch和live cancel确认返回归属；其他client的共享result即使很大，也不会在此client md/dd为0时写入。取消时controller优先退0，service清pending/owner及epoch，旧响应不能变成新calc结果。已有MA非法/闲置算口差异仍属于v4语义：非法Z请求在service消费前被取消；即使只看v4的ma34本身，Z0的b恒1，已经落在本表num界内。不能用恶意外部md/dd+任意64位result替代真实服务契约后宣称本证明失败。

## 无循环论证与泛型边界

先对**现有v4**执行按固定calc/return_state路径证明以上值界，再对新存储实现做首个差异归纳：初始num/value均0；每次有效写入旧值都落在新类型范围，低位保存后64位sign-alias逐bit恢复，保持后续请求/返回与状态相同；其余拍保留相同旧值。因而本次num64/value64别名在取消及idle阶段也可严格相等，不需要为它们新增MA式idle例外。

闭合调用表不读取position_px/py/qx/qy，POSITION_KP_Q16仅改变这些未使用寄存器声明宽度；不为非默认POSITION_KP引入额外乘积。支持的VELOCITY_FRAC_BITS仍为0/16，work gain用任意U16界而非bank的10000上限。其余泛型不产生新calc。若未来恢复位置外环或改分母/返回路径，本证明必须重审，不能按该表盲缩新操作数。

允许的最小实现：num寄存器改名为signed[49:0] num_store，声明64位signed num并补14个符号位，state100写目标改num_store；value_store改signed[38:0]，64位value补25个符号位。表达式、状态、请求/取消、分母、原module接口及延迟全部不变。可在实际RTL中逐拍比num/value64别名与v4，同时保留原控制/安全及合法service grant断言；资源和布线仍须新测量，不能从源码减少位数预报DSP节省。
