# v4：实际消费位宽与一拍非法数值边界

比较真实v3 `9aa6a51a...` 和v4 `ffddb029...` 控制器，各接独立的真实单客户端乘/除服务。v4只把ma存储50→34、mb存储34→28，并继续符号扩展成64位；没有修改服务、数值检查或取消时刻。完整范围证明在 `../build/operand_width_design.md`，55源由本目录inputs绑定，工具路径见执行脚本。

两种速度小数配置均使用非默认 POSITION_KP_Q16=98304。每个配置实际exit0：

| 项目 | FRAC=0 | FRAC=16 |
| --- | ---: | ---: |
| 逐拍比较控制/安全/归一化/参数边界端口 | 816534 clocks | 816534 clocks |
| 实际服务grant，操作数完全一致且满足34/28位 | 870 | 870 |
| Z发布 | 29 | 29 |
| 一拍非法az捕获：无该请求grant、无新发布 | 4 | 4 |
| 实际命中的math_a算口差异，未逐拍分类原因 | 48242 clocks | 48242 clocks |

比较全部222bit控制端口及数学request/cancel/status，每次实际grant检查held操作数，每次有效done检查真实返回结果；控制器state、XY/Z I及bias也逐拍一致。正常输入是24组有限压力组合，包括高度0/5000、正负速度与加速度边界、yaw正负18000、最大100000us逻辑XY dt和直接模块16位增益65535。它不是长时间稳定后的所有Z/倾角边界穷尽；65535是超出用户bank范围0..10000的直接模块压力值。保留全部原小数位，没有把协议合法范围缩小。

定向异常是INT32_MAX、INT32_MIN、30001、−30001各一拍，同height_update并存且不发sample_update，触发数值检查管线中最早的坏pending_az路径。坏calc可在cancel升高同沿产生，旧50位算口和新34位算口确实不同；服务在下一沿因cancel而不接受它，恢复后下一完整回调相等。没有通过force/preload跳过实际输入/服务时序，也没有为了让比较通过而修改产品取消逻辑。

这个定向测试使用单客户端服务，**没有穷尽其他client占用、旧owner响应与所有注入相位的组合**。这些取消隔离关系按未修改服务的pending/owner/epoch结构审计；独立四客户端非零XY/Z积分测试另记在 `../width_integration/`。本报告不把结构审计说成定向实测，不对闲置或已取消的math_a/b要求无条件相等。历史日志把差异计数命名为cancelled_or_idle，但计数器本身没有逐拍断言原因，应按上表的算口差异理解；实际消费数据另有严格断言。POSITION_KP当前没有算法读取，非默认参数没有额外覆盖新的运算路径。以上范围经独立只读夹具审查后补充，未修改已执行脚本或重写原结果。

实际结果见 `results.json` 与两份simulation.log；source_stability确认输入55源在测试期间未变。这个结果是RTL消费契约证明，不是布线时序、板上测试或飞行验收。
