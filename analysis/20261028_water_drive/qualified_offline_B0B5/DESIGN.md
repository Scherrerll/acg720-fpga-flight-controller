# B0B5 水上双电机独立候选：控制与实体边界

2026-10-28至29日，继承冻结 `firmware/B0B4/source` 的55个文件，只在本目录独立副本开发。当前最新为v8，最终采用哪版以精确位流的qualification为准。B0B4的源码、位流、清单和历史证据不回写，不继承其时序或实物资格。候选标识为UserCode / 参数响应B0B5；原B0B4参数客户端可能按版本拒绝，应保留这种拒绝。

## 尚未解决的实体条件

用户提供的照片显示两个红黑双线的推进电机，标称约 13000 转、36 mm 桨径、30 cm 线长；照片没有显示电调/驱动器型号、额定电压或电流。不能凭这张图认定已有兼容 PWM 的双向电调。双线电机不能接 FPGA IO 取动力，正反转需要匹配的双向功率驱动器。

RTL **假设**驱动器接受 50 Hz、1000–2000 μs，1000 反向、1500 停止、2000 正向。该假设来自先前方案讨论，尚无型号说明书或测量支持。若实际驱动器采用方向+占空比、刹车后再倒车、不同中位、单向电调等接口，本候选不适用，必须修改并重新验证。停止 PWM、1500 μs、断电三者的实际效果不能互相替代。

在实体安装前必须取得驱动器型号及厂家接口/电压/电流资料，并重新确认当前拆桨/推进桨隔离、CH5 低位、CH6/CH7 状态、实际板和下载器、引脚占用、VCCIO、电调共地及供电。不能沿用先前 B0B4 上电或冷启动的条件。本轮不打开串口、不操作下载器、不试转、不飞行。即使时序通过，也只形成待硬件条件核实的离线候选。

## 通道及混控

| 输入 | 水上约定 |
| --- | --- |
| CH6 | 1800–2200 请求水上；800–1200 请求飞行；中间值不允许切模式且撤销水上使能 |
| CH2 | 中位 1500，增大为前进 |
| CH4 | 中位 1500，增大使左侧推力更大；实际转向须安全台架验证 |
| CH5 | 800–1200 停机准备；1800–2200 使能确认；中间值撤销使能 |
| CH3 | 水上及切模式全程须 800–1100；不参与水上推力计算 |
| CH1 | 切模式和水上使能准备须中立，不参与水上混控 |
| CH7 | 保留原飞行模式，水上仅检查通道存在及有效范围 |

中立为闭区间 1470–1530 μs。CH2、CH4 在死区内为 0；死区外直接取 `channel-1500`，截到 ±500 μs。这是硬死区，边界外存在 31 μs 台阶，没有另加增益或重标度。左命令为 `1500+前后+差速`，右为 `1500+前后-差速`，各自截到 1000–2000。例：CH2/CH4=2000/1500 → 2000/2000；1000/1500 → 1000/1000；1500/2000 → 2000/1000；2000/2000 → 2000/1500。

两个正命令都表示朝机头方向的逻辑推力。左右桨型、安装方向、马达接线和 CH4 遥控方向未实测，不从产品图片推断旋向；安全台架逐台确认后才决定是否调整驱动器方向。镜像安装时两台电机的轴旋转方向可能不同，逻辑推力方向仍须一致。

## 模式互斥

复位默认飞行选择，原飞行解锁仍需原有低位/高位流程和健康条件。CH6 在飞行已解锁期间变化不切模式、不切断飞行输出，避免单个开关导致空中进入水上。只有同时满足以下条件，连续保持 25 ms 后才提交 CH6 模式：新鲜完整遥控包、CH5 低位、CH1/2/4 中立、CH3 低位、飞行未解锁、无起飞状态、无有效飞行命令、四路飞行有效宽度均为 1000、飞行 PWM 非活动状态。

地面在 CH5 低位提出水上请求，会锁住飞行准备，即使摇杆不满足条件而请求被拒绝，也不能随后误解锁飞行。该锁只有满足上述停止条件并明确选择 CH6 低位才能解除。v4/v5 水上模式锁存后，飞行 gate 的健康入口被禁止，原 live 条件通过下述不变量自然保持停止；原控制和保护算式不变。

这里的“停止”指 FPGA 解锁、命令和 PWM 有效值的逻辑状态；当前没有转速、落地或接水传感器输入，不能据此证明旋翼已机械停转或飞机已在水面。

水上转回飞行也须停止、中立并连续至少25ms，覆盖一个水上20ms帧和至少十个飞行2.5ms帧，撤销水上命令后的旧脉冲已经结束。回到飞行后还须原CH5解锁流程。未激活水上且CH6低位的飞行路径与B0B4做有界对比；不宣称所有任意输入轨迹的形式等价。

## 新鲜度、故障及重新使能

### 候选修订中的 gate 不变量

早期 v2/v3 在 `live_armed_conditions` 也直接加入 `flight_permitted`。网表检查显示，该模式信号经组合逻辑影响1127个原飞控寄存器引脚，增加了原停止/导航/遥测路径的耦合。独立 v4 保留 `control_gate.sensor_ok` 中的模式禁止，以及水上使能中的原始解锁/停止检查，恢复原 B0B4 的 `live_armed_conditions` 表达式。实际采用哪版由最终 qualification 的 `rtl_revision` 和源码哈希确定。

从复位起，`!flight_permitted -> !armed_raw` 可按时钟边沿归纳：初值为未解锁；禁止位从0变1的所有分支都要求旧CH5低位且旧`armed_raw=0`，而原gate只在CH5高位才能置位armed，因此同一边沿不能新解锁；旧禁止位为1时，gate健康入口必为0，下一状态armed必为0；禁止解除的边沿旧健康入口仍为0，且解除也要求CH5低位。因此模式切换、RC故障/恢复、开关往返及复位均保持此不变量。

原 `command_fresh` 必须经过armed条件，PWM的frame_active又必须经过command_fresh；所以被禁止的飞行侧自然维持原1000us停止输出，不必把新增模式信号直接接到整个原组合停止链。独立压力仿真还使用最低1拍低/高确认及模式等待，扩大竞态机会，300000拍覆盖1665次飞行解锁、3992次水上使能和11275次模式边沿，检查禁止=>未解锁以及使能互斥。它是有界仿真加人工归纳论证，不标成形式工具证明，也不替代真实50MHz物理验收。

水上要求7–8个通道；CH1–7及存在时的CH8均须800–2200，沿用原PPM解码器整帧原子提交。watchdog只在控制器采样到有效`rc_update`时清零。当前v7/v8以共用1ms使能计数，从最后接纳新帧起约99–100ms失效，100ms是上限；原v2–v6的精确5000000拍实现保留在旧副本。原飞行解码器的500ms timeout不改写。坏间隔、缺通道、原解码器失效等条件仍每个50MHz时钟检查，立即撤销水上健康条件，不把保持值当新包。

这里的新鲜度指 **FPGA 收到的 PPM 帧**。如果无线失联后接收机仍连续发送保持值，FPGA 无法从这些帧区分无线健康与保持；接收机必须在安全台架验证失联时停止有效 PPM 或输出 CH5 停机及中立值，不能用仿真宣称无线失联行为已合格。

水上必须在所选模式、健康遥控、CH3低位和飞行已停止的条件下，CH5低位且CH1/2/4中立连续至少0.5s，再高位且仍中立至少0.5s，才置位使能。v7/v8每段约500–501ms，首个不完整计时间隔不算入最低等待。使能后CH2/4才可离开中立。任何遥控失效/超时、范围错误、CH6不再高位、CH3不再低位、CH5不再高位、飞行侧异常活动或复位均逐时钟撤销使能并清空准备；健康恢复或CH6切回而CH5一直高位不能重启。

### 共享计时资源（v7/v8）

新增水上块把69位高速年龄/模式/确认计数，改为16位50000拍分频、7位年龄、5位模式及9位共用低/高确认计数。最低保持向上取整并补完整首间隔；失效期限向下取整，保留100ms最长新鲜度。连续条件断开时每个clk都清除状态，包含两个1ms使能之间只有一拍的故障。生产默认模式等待为至少25ms、约26ms内（最多另含一拍请求观察），低/高确认各至少500ms、最多501ms。精确周期界限记录在源码审计的`water_timer_contract`。

默认50000拍节拍经过真实50MHz仿真测量；测试还在七种节拍相位、不整除的等待长度下无force地检查完整保持、超时上限、一拍故障及高位恢复锁定。仅快速场景的`TIMER_DIVISOR=1`保留旧逐拍时间，不能当作生产毫秒测试。水上控制块综合由128FF/260LUT原语降为96FF/211LUT原语；两路PWM模块不改。

## PWM 边界、反向与上掉电

50 MHz 由 50 拍产生 1 μs 计数，20,000 μs 一帧，两路在同一边界锁存宽度。命令夹在 1000–2000。两个输出脚由专用寄存器驱动，计数器组合比较不直接连接引脚；综合网表另查 OBUF 的数据端确实直接来自寄存器 Q，避免将 RTL 无毛刺误当作组合电路无毛刺证明。初始/复位期间信号低；复位释放后先等待完整 20 ms，再开始中立脉冲。复位本身会截断在途脉冲，必须核实实际驱动器如何处理短脉冲/无信号。

正常撤销使能完成已开始的完整脉冲（最长 2 ms），下一帧为 1500 μs；因此从撤销到首个完整中立脉冲开始最长 20 ms。不会把一帧拆成两个脉冲，也不会把正在发送的 1000 μs 反向命令直接延长成中立。即使只丢失一个时钟的使能，也保留中断并插入完整中立帧后再接受活动命令。

任一侧请求的非零方向与上次非零方向不同，两路共同发送中立，直到至少完成 15 个完整中立帧（≥300 ms）；实现保守地可能多一个帧。任一侧长期中立也只有在两路共同完成中立等待后清除方向记忆。该等待不能代替驱动器自身的换向协议，未假设可以直接改变电机电源极性。

电机/驱动器可能先于 FPGA 上电、独立重启，或 FPGA 先掉电。RTL 不能检测目前未接入的驱动器供电状态，也不能保证掉电高阻时驱动器的信号解释。台架必须验证：无 PWM 不转、持续中位不转、上电不自校准/不误转、FPGA 复位不误转、驱动器断电重启不沿旧命令恢复；必要时由匹配的硬件使能/断电互锁解决，不能靠“仿真通过”略过。

## 同拍传感器谓词缓存（v5）

v4 的 B18/C18 P2/R0 和 P3/R0 均完成布线，但 setup 分别为 −1.703 ns 和 −0.280 ns，不能通过真实50MHz资格。P2/R0 的原始最差路径由 MTF 原始距离经有效性、垂向可用和手动角度 CE 形成；其中有一段4.998 ns的长网络。v5 在独立候选中仅改变 `sensor/mtf01p_reader.v`：原 TOF==1、无符号距离10–12000谓词在同一有效帧接纳边沿，依据将要发布的同一帧数据存入一个寄存器。raw_frame 与缓存具有相同初值、复位、接受、保持和错误处理所有权；数据、阈值、算术及所有公开输出的发布周期不变。外层 `mtf01p_reader` 接口不变；内部 observer 新参数默认0，保留独立调用者原表达式。

修改前后均通过同一实际 UART 驱动的 B0B4 参考逐拍对比；最终v5的完整11项验证包含1,563,958次比较、441个样本、172次距离有效性边沿，覆盖边界/随机32位距离、TOF、质量、加和校验错误、长度、未知消息ID、UART错误、超时、复位、时间纪元、诊断冻结及200ms新鲜度。协议帧本身使用8位加和校验。

新鲜网表中的 `payload_range_ok_q_s0` 确为 DFFRE，时钟/复位/使能与原始帧寄存器相同，缓存到指定手动角度CE的组合深度为13。原始距离仍通过 flow/geometry 的其他条件影响该CE，最长拓扑深度仍为17；不能据此宣称所有关键路径都已缩短，更不能代替最终布线STA。该改动的人工归纳依据是：初值两表达式均为假；有效帧边沿数据与谓词同时替换为同一新帧；其他边沿二者保持。因此缓存对所有可达帧等于原组合谓词，有界逐拍仿真作为补充证据。

### 第二个同拍谓词（v6）

v5网表仍有原始距离经flow相关比较共享逻辑影响相同CE的17级分支。独立v6进一步缓存原 `range_numeric_ok && distance_mm>=80 && flow_status==1 && quality!=0` 的帧内部分，新鲜度仍使用同一时刻的原 `link_fresh`。缓存由同一个 `next_raw_frame` 计算，和raw_frame、距离缓存同一有效接纳边沿更新；重置为假，其他边沿保持。新增内部 `PRECHECKED_FLOW` 默认0，外层reader启用1，保留独立observer调用者原路径。

修改前先扩大同一测试台的flow_status=0/1/2/255及非零quality=1/200/255覆盖，v5先通过同一1563958次逐拍比较，再修改v6；v6完整11项验证全部通过（`sim_20261028T161625149856Z`）。归纳论证与v5相同：帧字段及两个谓词在同一所有权边界上原子替换，reset/hold相同，故所有公开数值、故障及发布时序保持原行为；仿真是有界补充，并非形式工具证明。

v6新网表保留两个DFFRE，均和原帧同CLK/RESET/CE。指定CE的缓存距离分支深度12，原始距离剩余geometry分支15（v5为17）；flow缓存经1级LUT到flow输出，没有直达该CE的组合路径。其他原始几何比较仍存在，完整50MHz布线/STA须重新验收，不能从逻辑深度或v5结果推出通过。

## 引脚比较依据

### 几何高度生产者的范围不变量（v8）

v7的F18/F19 P3/R0完成布线但setup为−0.626ns，实际最差路径由几何`height_mm`经height_fusion重复范围检查进入原核心诊断CE，16级逻辑、16.063ns布线延迟。原几何模块的高度初值为0，清除任务写0；唯一其他赋值在有符号`pending_height`满足0–5000的分支内发布。因此从初始化起每个RTL可达状态的输出都在0–5000，包含复位、取消、保持和故障。

v8给height_fusion增加默认0的`REF_HEIGHT_BOUNDED`参数，只在上述内部生产者连接的实例启用1。该实例省去重复输入范围组合检查，其他调用者默认保留原检查。几何发布前范围保护、height_fusion其他当前健康检查、事务保护、数值计算、系数、ROM、状态机和公开发布周期全部保留。源码审计逆向撤销该两处改动后，整个导航和高度融合文件精确恢复B0B4；几何生产者文件字节不变。这是RTL生产者契约下的归纳论证，不是硬件故障注入或形式工具证明。

修改前、最终v8修改后使用同一完整导航比较：1042位公开输出逐拍检查2720105次，67次几何发布、4次高度发布、1213627个ready周期及95次重叠；每拍断言几何高度范围。使用实际共享数学服务，包含边界距离、故障、取消、恢复、诊断冻结及数值输出。一次300秒模拟器墙钟超时记录保留，未计为通过；最终13项整套验证完整通过。新网表中该高度字至原core CE/RESET/SET的图模型可达引脚对11662→0；这不代替新布局的完整20ns STA。

原理图 GPIO0 使用可选择的 VCCIO，须实测 P6 选择及 TP5 约 3.3 V；不能把原理图旧 Bank 标签直接当成 Gowin 内部 bank 编号，实际封装 bank 以本次 vendor IO 报告为准。新增约束设 LVCMOS33 / BANK_VCCIO=3.3 / DRIVE=4 / PULL_MODE=NONE，全部原约束和唯一 radio_rx 同步器边界例外保留，不新增时序例外。同一RTL修订的各组候选使用同一新鲜综合网表独立完整布线，综合结果不从 B0B4 借用。

最终比较必须同时记录布线是否完成、未布通网络、报告提供的拥塞指标、布线耗时、setup/hold/recovery/removal/最小脉宽及原关键路径。若工具没有输出数值拥塞率，就明确记录“未提供”，不能把一次更快的布线当成拥塞率实测。只在 20 ns、所有适用检查合格的候选之间按裕量及接线取舍选择；有限候选比较不证明全芯片的全局最优引脚。
