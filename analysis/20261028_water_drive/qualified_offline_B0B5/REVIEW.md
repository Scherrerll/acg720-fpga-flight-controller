# 离线设计复核记录

本轮为主代理自审与工具核对，没有独立人员或子代理审查，不将本文件标成独立审查通过。

1. 初始 `rtl/water_pwm_pair.v` 仅能产生波形，缺少模式、健康和重新使能所有权，动态 `stop_us` 也不足以证明停止语义。各版构建只使用明确指定的`candidate_v*/source/water_*.v`，`candidate/source`为最终提升入口。旧`rtl/`和旧两个测试台未用于新网表。
2. 水上反向时不能沿用单向飞行 PWM 的“至少 1000 μs 前缀后缩短”策略：那会把反向信号错误当作停止。新增 PWM 完成当前完整脉冲并在下一帧切中位，同时记住一次使能中断，禁止帧内重启。复位的无信号语义单独列为硬件待验证项。
3. 飞行中直接将 CH6 组合到总停机逻辑会造成误碰开关空中停转。模式在 CH5 低、低油门、中立及飞行已停稳条件下锁存；已解锁飞行不接纳 CH6。地面拒绝水上请求后仍锁住飞行准备，避免操作者以为已选水上而意外解锁四旋翼。
4. 接收机保持值不等于新包，采用真实 `rc_update` 驱动独立新鲜度。FPGA 能检测 PPM 失效，不能仅从持续发送的保持帧检测无线链路失效。接收机 failsafe 必须台架核实。
5. 所有模式/水上故障清除低位准备和高位确认，高位恢复不得重启；界限同时包含缺 CH6/7、存在但越界的 CH8、CH6 中位、CH5 中位和水上 CH3 离开低位。
6. 共享 CH5 必须禁止飞行 gate 在水上解锁。核心健康入口互锁，水上再检查飞行原始解锁/起飞/命令/PWM 状态；v4/v5通过第14项不变量恢复原live条件。模式转换 25 ms 停稳等待跨过完整水上和飞行 PWM 帧。
7. 水上新增块使用窄位宽、加减/比较和微秒计数，无乘法 DSP，保持原资源紧张工程的可布线性。三组引脚用同一新网表完整布线；没有因未通过而降低频率或放宽时序例外。
8. B0B4 55 个源输入、发布镜像及清单以有界哈希守卫保护；未读取 `.env`、`deployment.env`、凭据或 B0B2 的禁读压缩包。构建目录仅追加，失败尝试保留。vendor 生成的 `.gprj.user` 是辅助产物，检查显式声明的 57 个源码，避免把辅助文件的存在误报为源码修改。
9. 初次派生 PNR 工程的 XML 序列化产生了重复 XML 声明，被 vendor 以真实退出码 1 拒绝。修复构建脚本为单一声明后使用新目录重新执行，没有改写失败日志或把 runner 的退出码当成 vendor 通过。
10. 原参数通信版本必须与新固件区分，因此 UserCode 和 A591 feature 标识改 B0B5；XY 默认 P/I 和协议行为未改。不提供伪装 B0B4 的兼容路径。原地面参数工具可能拒绝新版本，这是待后续明确支持的限制。
11. 自审发现新 PWM 的组合计数译码直接驱动引脚，RTL 仿真无法排除物理组合毛刺。改为两个专用输出寄存器，保留精确脉宽、完整帧和异步复位静默；原 v1 三次 PNR 在完整布线前主动中止并记录真实退出码 4294967295。v2 重新综合，网表须证明输出缓冲直接由寄存器 Q 驱动，再从新网表比较引脚。
12. v2 的 P3/R0 完整物理尝试未通过：B18/C18 与 B18/C19 均 642 条未布通，F18/F19 为1190条，三个 vendor 实际退出码均为1，没有生成可验收 STA/位流。原CLS使用26399，新候选26533（均约89%）；这些事实说明原布局配方不能直接继承，不能单凭资源总量尚未满就宣称可布线。继续用同一已完成的新网表分别比较P2/R0和P3/R1，不改RTL、SDC、频率或功能。
13. 后续 v2 普通配方仍未布通。独立v3只精简新增水上块：互斥的低/高确认共用计数器，混控由3级改2级（60ns改40ns，均远小于20ms PWM帧）。水上控制块少48寄存器/55LUT，整体少47寄存器/24LUT，DSP不变；全部8项验证通过并重新综合，没有把v2的物理结果当作v3资格。
14. 网表追踪发现，直接把mode禁止加进原live组合条件会影响1127个原寄存器引脚。独立v4保留gate健康入口的禁止及水上对飞行armed/stop的检查，恢复B0B4的live条件；设计文档给出从复位开始的禁止=>未解锁归纳论证。新增300000拍快速仲裁压力测试及实际core断言通过，连同原8项共9项。新网表该组合影响降至255个原寄存器引脚，整体比v3再少53LUT。v4仍必须另行完成所有物理资格，不从仿真或原B4借用时序结论。

15. 补充v4端到端实模块联调，穿过PPM解码、原gate、新水上控制/PWM及原飞行PWM；验证1800/1600差速、反向共同中立等待后1200/1200、丢帧1500、高位恢复持续超过0.5s不能重启，以及水上已中立后原飞行1300。v4共10项检查通过；缩放计时的联调与生产终值/真实50MHz波形分别保存，避免把缩放场景称作真实时间测试。
16. v4 B18/C18两次完整布线的正常vendor退出均0，但P2/R0和P3/R0的setup分别−1.703/−0.280ns，明确拒绝物理资格。P2/R0最差路径是原MTF距离到手动角度CE，并含4.998ns长网。v5只在独立副本中缓存原距离有效性谓词，和raw_frame同一有效接纳边沿更新，复位/保持/错误所有权相同；阈值、算术、公开接口和发布周期不变。
17. v5修改前后均使用相同B0B4实际UART参考逐拍对比。最终完整11项检查全部通过，包含1,563,958比较/441样本/172有效性边沿；边界、随机32位高位、状态/质量、加和校验及错误/超时/复位/诊断冻结/新鲜度均覆盖。网表确认缓存DFFRE与原帧同CLK/RESET/CE；缓存分支至指定CE深度13，但原始距离的其他flow/geometry分支仍可达该CE、深度17，故不据此提前宣称时序改善。
18. v3 B18/C18 P2/R0在报290条未布通及Tcl错误后等待超过80分钟未返回。Windows仍枚举到vendor条目且报告HasExited=True，runner没有正常p.wait回执；已停止该离线Python runner，保存中止原因和日志哈希，vendor退出码保持未知。它作为中止失败项参与矩阵，不能伪造正常退出码或套用其他尝试的STA。

19. v5 P3/R0四组均未布通，依次为B18/C18=1120、B18/C19=1120、F18/F19=1007、A13/A14=357；B18/C18 P2/R0=543。五个vendor正常退出码均1，没有完整STA资格。P4/R0作为手册支持的另一布局策略另行记录，不改变频率、SDC或功能。
20. 独立v6把同一帧的flow有效性条件一并缓存，数值计算、范围阈值及公开发布周期不变。先扩大flow_status与quality覆盖并在修改前通过同一B4对比，再改动；最终全部11项验证通过，含1563958比较/441样本/172距离边沿。源码允许改动逆向撤销后整份MTF/core/top精确恢复；两缓存DFFRE同原帧CLK/RESET/CE。指定CE的距离缓存分支12级，剩余原始距离geometry分支15级（v5=17），flow缓存经1级LUT到flow输出；没有把拓扑深度当作物理时序通过。
