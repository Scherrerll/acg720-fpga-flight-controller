# 2026-10-23～24 工作记录（北京时间）

## 10-23：测距失效接管与综合/布线排查

B0AF 增加了测距失效后的手动油门接管，以及重连后不自动抢回高度控制的处理。相关回归覆盖组件、核心、正常路径、线协议和工具。历史源码及原始资格、失败和硬件拒绝记录保存在 [B0AF 阶段](../history/14-b0af-height-loss/)，这组记录不代表当前可用默认版本。

随后 B0B0 针对综合映射和布线压力进行调整，包括解析器提交帧视图、诊断发布、就绪与速度资格的等价重排，以及倾角发布路径。各阶段的原始工具、源码合同、证明和失败报告保存在 [B0B0 阶段](../history/15-b0b0-routing-stages/)及当前候选的关联证据中，失败试验按原结果保留。

官网前端改善慢响应与短暂断连后的恢复：1/2/4/8/10 秒退避，慢请求结束后不再额外空等一秒；远端仍有效但请求延迟较大时保留并明确标注延迟读数，不将陈旧数据标为 fresh。相关代码和测试随本次提交上传，不回填 Git 历史时间。

## 10-24：布线收敛、拆桨验证和固化

当时的 [B0B0](../firmware/B0B0/) 在同一份精简网表上完成物理收敛：零未通，51.608 MHz，19.5 ns 约束下 setup/hold 零违例；硬件时钟仍为 50 MHz。44 份 Verilog、51 份源输入和选中位流均按哈希冻结。原始包的 88 个文件和 677 项关联证据在工作区复核通过。

补充了倾角全部 65536 个数值门槛、就绪与速度资格等增量证明，以及 MTF UART、解析和度量的 13 项边界测试。测试脚本问题只在记录过的验证适配层修复，原断言、向量和固件行为没有改变；整个当前顶层/综合网表等价验证没有重新执行。

实物拆桨测试完成了启动、正常高度控制、测距断流后手动接管与恢复保持、横滚和静止对照、一分钟融合、四向带动力纠偏、默认 Flash 固化及仅电池冷启动。数据、操作者的原始确认和限制见[当天验证](../validation/20261024/)；较大的 JSONL 使用无损 gzip 保存，完整原始串口流仍在本地。

用户确认此前掉动力来自电池松动，并接受最低油门持续后的落地锁定行为。记录中区分了用户说明和软件能够独立证明的事实。

## 官网链路修复

8765 正常接收 COM17；8767 同时选择 COM17 时因串口已被占用而拒绝访问，切回正在接收的无线页面即可。公网无数据的直接原因是 8766 HTTP-only 转发进程未运行，公网仍保留旧 B0AC 快照。恢复旁路并按用户请求开启实时分享后，公网连续返回有效 B0B0 和递增序号，未改 FPGA、电台或接收器。

新增 `web/flight-console/local/start-live-share.py`：复用现有 8766，不重复打开串口；从原有私密配置读取发布凭证，通过子进程 stdin 传递。仅显式 `--enable-sharing` 才启用分享。默认 bridge 启动仍不自动分享；未自动上传任何历史飞行日志。启动器单独覆盖 5 项离线合同检查。公网核查样本见 `validation/20261024/web_relay_recovery/recovery_samples.json`。
