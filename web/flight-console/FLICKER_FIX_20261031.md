# 本地监控图表闪烁修复 · 2026-10-31

## 现象与证据

本地8766页面的曲线、姿态及部分数值会短暂变暗再恢复。修复前约10秒44组HTTP采样中，8765接收端均报告有效，桥接出现一次缓存年龄504.91ms越过500ms有效期，以及一次年龄164.25ms但源状态不匹配。页面每次绘制立即按严格fresh切换`.is-stale`，该类将透明度降到48%，因此短暂状态变化会表现为明暗闪烁。

另一个绘制问题是每帧都写canvas.width/height。离线回归在旧代码上确认：画布尺寸未变，下一动画帧的宽高赋值次数仍从5/5增加到6/6。同步清屏未单独证明会露出空白帧，但频繁重置缓存没有必要。

## 修改

- 绘图仅在CSS尺寸或DPR变化时分配对应画布尺寸；每帧用setTransform覆盖缩放并clearRect清屏，避免累积缩放和旧曲线残影。相同文字不反复替换DOM文本。
- 本地桥接从250ms改为50ms取样，浏览器本地轮询从200ms改为100ms。单请求在途、后台页面暂停保持；公网浏览器及上传仍为1秒周期。
- 旧接收程序的分锁快照偶尔无法通过序号校验时，仅重新GET一次，再用同一规则验证；两次均不匹配或过期仍无效，不补齐数据，不放宽有效期。
- 视觉灰显有250ms延迟及350ms渐变；短暂波动恢复时取消待执行的灰显。状态文字和有效性标记即时更新，持续失效仍正常灰显；尊重减少动画设置。
- 当前B0B4接收器最终Dashboard在构造、交给线程前使用RLock，整个派生snapshot同锁生成。强制线程交错在旧代码复现主帧/info为10/11，或主帧/info/诊断为10/10/11；新代码完整回归91/91通过。冻结support和旧版本保持原样。

500ms源有效期、合法序号差值、未知/失联处理以及P/I停机条件均保持。此次没有写入飞机参数或烧录固件。
