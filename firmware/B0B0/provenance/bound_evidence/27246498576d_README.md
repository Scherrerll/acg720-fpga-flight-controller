# Navigation diagnostic reset contingency

This directory contains a proposed patch and an isolated RTL proof. Nothing is applied to the fixture or active variants. No Gowin synthesis or PNR is run.

Only `diagnostic_q` changes. `STARTUP_ONLY_DIAGNOSTIC_RESET` defaults to zero. The proposed top explicitly enables it; all generic callers retain the original reset branch. The initial `RESET_DIAGNOSTIC` value and the post-register output mask remain byte-for-byte unchanged. The opt-in branch captures only when `rst_n && !diagnostic_hold`.

## Inductive equivalence argument

The actual top declares `boot=0`, increments it only while it differs from 255, and defines `rst_n=boot==255`. Thus reset is initially asserted, releases once and cannot reassert. During this initial low-reset interval, the reference repeatedly writes `RESET_DIAGNOSTIC`; the opt-in bank holds that same initialization. When reset first releases and on every subsequent edge, both banks either capture the identical complete 720-bit `diagnostic_next` or hold according to the identical `diagnostic_hold`. Their registers and unchanged output masks are equal by induction for every possible payload and hold sequence. This argument is independent of origin-reset behavior because `origin_reset` is not an input to the bank: its upstream effects enter through the unrestricted payload.

With the parameter zero, the original reset branch remains exactly intact, including any number of runtime resets. The opt-in configuration is intentionally not valid for callers that reassert reset.

## Reproduction and scope

Run `python prove.py` from any directory. The script extracts the original and proposed bank plus original output mask from saved fixture sources, embeds the exact top boot-counter RTL, and compares all bank bits and all output bits after initialization and every edge for 50,000 cycles. It exercises long and random hold intervals, changing all 720 payload bits, startup release while held, and repeated runtime resets for the default configuration. A deterministic LFSR seed makes the run reproducible. Files and temporary compiler outputs stay in this directory. Source hashes are checked before/after.

This is bank-level RTL simulation plus an inductive source argument, not full-top, UART, formal-tool, or synthesized-netlist equivalence. The bench's origin flag is descriptive stimulus only; arbitrary full-payload variation covers the bank boundary. No integrated origin-reset claim is made.

## Expected physical effect and acceptance gate

Original SYN has 588 retained diagnostic payload FFs: 550 DFFRE and 38 DFFSE, all with `n13_16` reset/set. Removing their reset connections does not remove their storage. New CE gating may cost logic; CLS improvement is unknown.

Before any acceptance, compare original and candidate synthesized physical FF INIT values and logical bit mappings for every retained diagnostic bit; especially verify former DFFSE bits still initialize to one when mapped to a non-set FF. Account explicitly for constants, aliases, inversions, and merged registers. Verify the complete 720-bit power-up value equals `RESET_DIAGNOSTIC`, the same output mask remains, reset is absent only from this bank, and CE is precisely qualified by reset release and snapshot hold. Preserve source and tool-option hashes. Then run full-top UART byte, acceptance-cycle and snapshot-hold equivalence including the first frame, origin events, and held-data changes. Successful bank simulation alone does not establish physical initialization or route acceptance.

## Completed actual-top comparison

`full_top.py` completed 4,935,299 cycles comparing two actual top-level RTL instances and all actual dependencies. Each UART transmitted two complete 568-byte composite sequences, 1,136 bytes total, with exact equality of every acceptance cycle and byte, TX/radio wire level every clock, snapshot hold, sequence/start, and navigation bank/output bits. Coverage includes 4,950 payload changes while held and 399 periodic origin events. `check_packets.py` independently verifies two each of A579, A57A, A580, A581, A582 and A583, sequence numbers 0/1, all XOR/CRC values, and differing navigation payloads across frames.

Simulation qualifications: telemetry PERIOD is overridden to 512 on both instances instead of production 10,000,000; boot counter and UART baud remain actual, unchanged RTL. Sensor input pins are constant. Both instances' `diagnostic_next` are identically forced to deterministic changing full-width payloads; both `observer_reset` wires are identically forced to periodic origin events. Snapshot bank, output mask, serializer, UART, snapshot-hold and sequence state are not forced. Thus this proves the changed bank in the actual complete serialization/hold path, not end-to-end physical sensor behavior or production-period startup time. No reset-removal acceptance is inferred for runtime-reset callers. Physical INIT verification remains required.

Run `python full_top.py` then `python check_packets.py` to reproduce. No unchanged bank proof rerun was performed to add hashes. `artifact_manifest.json` binds all study sources, proposed patch, harnesses, scripts, compiled images, logs and proof reports, and all original full-top dependencies. Reports state their scope separately from artifact identity.
